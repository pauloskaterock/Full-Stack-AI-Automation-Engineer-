---------------------------------------------------Conceitos básicos obrigatórios
Elemento	O que é	Exemplo
Evento de Início	Onde o processo começa	"Processo recebido"
Evento de Fim	Onde o processo termina	"Processo concluído"
Tarefa	Ação que deve ser executada	"Aprovar processo", "Enviar email"
Gateway	Ponto de decisão	"Valor > 10.000?"
Fluxo	Conecta os elementos	Setas que ligam as etapas
Tipos de Gateway (importante!)
Gateway	Quando usar
Exclusivo (XOR)	Apenas UM caminho é escolhido (se X, faz A; se Y, faz B)
Paralelo (AND)	Todos os caminhos são executados ao mesmo tempo
Inclusivo (OR)	Um ou mais caminhos podem ser escolhidos

Tipos de Tarefa

Tarefa	Descrição
Usuário	Precisa de interação humana (ex: aprovar, preencher)
Serviço	Automática (ex: enviar email, integrar com sistema)
Script	Executa código (ex: calcular valor)
Manual	Feita fora do sistema (ex: assinar documento)
Exemplo prático de BPMN
text
[INÍCIO]
    ↓
[Receber Nota Fiscal]
    ↓
[Gateway - Valor?]
    ↓
    ├─ < 5.000 → [Inserir no Banco] → [FIM]
    ├─ > 5.000 → [Enviar Email] → [FIM]
    └─ = 0 → [Contabilizar] → [FIM]
---------------------------------------------🔧 2. Automação de Processos
Conceitos-chave
Termo	O que significa
RPA	Robotic Process Automation (robôs que executam tarefas repetitivas)
Workflow	Fluxo de trabalho automatizado
Regra de negócio	Condição que define o que fazer (ex: "se valor > 5.000, enviar email")
Orquestração	Coordenar vários sistemas/processos
Abordagem para automatizar
Entender a regra – O que o negócio precisa?

Mapear o fluxo – Como as etapas se conectam?

Identificar decisões – Onde tem "se/então/senão"?

Configurar na ferramenta – Low Code ou código puro

Testar – Validar cenários possíveis

Documentar – Registrar como funciona

----------------------------------------------------------🧠 5. Raciocínio Lógico
O que vão avaliar
Habilidade	Como demonstrar
Pensar em etapas	Quebrar problema em partes menores
Tomar decisões	Usar "se/então/senão"
Otimizar	Buscar soluções mais simples
Antecipar erros	Pensar em cenários de exceção
Exemplo de raciocínio
Problema: "Processos até R$10k são automáticos, acima disso precisam de aprovação"

Solução lógica:

text
1. Receber processo
2. Verificar valor
3. Se ≤ 10.000 → aprovar automático
4. Se > 10.000 → enviar para gestor
5. Gestor aprova → finalizar
6. Gestor recusa → arquivar

Pergunta	Resposta esperada

"Diferença entre tarefa de usuário e serviço?"	Usuário = humano, Serviço = automático
"Como modelaria uma aprovação?"	Tarefa de usuário + gateway de decisão

Pergunta	Resposta esperada
